# Commenting and Documentation Examples

This repository contains complete commenting and documentation examples for **C++** and **Python**. The two examples use the same small program structure so that the focus remains on software-engineering practice rather than language-specific problem solving.

- [C++ example](./c++/) — see the README inside the folder for the complete C++ commenting and documentation standard.
- [Python example](./python/) — see the README inside the folder for the complete Python commenting and documentation standard.

## Purpose

The repository demonstrates how source code should be documented, organized, and maintained as professional software rather than treated as isolated assignment code. The examples emphasize:

- clear module, class, function, and method documentation;
- consistent commenting conventions;
- separation of interface from implementation;
- modular program structure;
- meaningful names and language-appropriate style;
- documentation that describes behavior rather than obvious syntax; and
- keeping documentation accurate as the software changes.

The C++ and Python examples follow the conventions of their respective languages rather than forcing one commenting style onto both.

## Academic Use

Some requirements in these examples are intentionally more explicit than typical production documentation. In particular, students are required to document categories such as parameters, return values, exceptions, and notes even when the answer is `none` or `None`.

This is deliberate instructional scaffolding. The goal is to make the programmer consciously consider each part of a function's interface and behavior rather than leave it unclear whether something was absent or simply overlooked.

The example-specific READMEs explain these conventions, the professional standards behind them, and the reasons for any intentional teaching deviations.
